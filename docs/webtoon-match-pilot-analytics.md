# 웹툰궁합 파일럿 분석 가이드

## 목적

W7-A에서는 정식 관리자 화면 대신 Supabase의 집계 뷰와 JSON 내보내기를 사용한다. 파일럿에서 질문 이탈, 선택 쏠림, 결과 분포, 공유 전환, 결과 정확도 반응을 확인하기 위한 최소 구성이다.

## 수집하는 정보

- 랜딩·테스트 시작·섹션 진입·완료·결과 조회
- 질문 ID와 선택 키, 선택/해제 여부, 좌우 배치 버전
- 완료 시간, 1위 장르, 별 집중도, 설정 선택 수
- 링크 생성, 공유 시도, 궁합 결과·랭킹 조회
- 사용자가 누른 결과 정확도 평가

다음 값은 분석 이벤트에 수집하지 않는다.

- 닉네임, 연락처, 이메일 등 식별 가능한 입력
- 원문 응답 전체
- 취향 벡터와 내부 궁합 계산값
- 링크 관리 토큰

브라우저에는 실패 재전송을 위해 최대 200개의 이벤트만 임시 보관하며 서버에는 한 번에 최대 20개를 보낸다. 서버는 이벤트별 화이트리스트에 없는 속성을 다시 제거한다.

## Supabase 적용

애플리케이션 코드는 분석 마이그레이션이 적용된 뒤 정상적으로 이벤트를 저장한다. 프로젝트 루트에서 사용자가 직접 실행한다.

```bash
npx supabase db push --dry-run
npx supabase db push
npx supabase migration list
```

적용 파일은 `supabase/migrations/202609130001_webtoon_match_analytics.sql`이다. 테이블과 다음 읽기 전용 집계 뷰가 생성된다.

- `match_pilot_daily_funnel`: 일별 방문·시작·완료·공유 퍼널과 평균 완료 시간
- `match_pilot_section_metrics`: 섹션별 도달 사용자와 평균 도달 시간
- `match_pilot_choice_distribution`: 질문별 선택 분포
- `match_pilot_result_distribution`: 1위 장르·별 집중도·설정 선택 수 분포
- `match_pilot_accuracy_feedback`: 결과 정확도 평가 분포

테이블과 뷰는 `anon`, `authenticated` 역할에서 접근할 수 없고 서버 DB 연결로만 읽고 쓴다.

## 파일럿 리포트 내보내기

`.env.local`에 서버 연결 문자열이 설정된 상태에서 다음 명령은 다섯 집계 뷰를 JSON으로 출력한다. 연결 문자열 자체는 출력하지 않는다.

```bash
npm run report:match-pilot
```

파일로 보관하려면 사용자가 직접 출력 위치를 지정한다.

```bash
npm run report:match-pilot > webtoon-match-pilot-report.json
```

생성된 리포트에는 집계값만 들어가지만 외부 공개 전에는 작은 표본으로 개인을 추정할 수 없는지 확인한다.

## 파일럿에서 볼 기준

- 시작 대비 완료율과 평균 완료 시간
- 섹션별 도달 인원 급감 지점
- 질문별 한 선택지 쏠림 및 거의 사용되지 않는 선택지
- 별 집중도와 설정 무관심 선택 비율
- 결과 조회 대비 링크 생성·공유 시도 비율
- 정확도 평가에서 부정 응답이 집중되는 결과 유형

표본이 충분히 모이기 전에는 질문이나 점수식을 성급하게 바꾸지 않는다. 파일럿 종료 뒤 보관 기간과 삭제 정책을 확정하고, 그 전까지는 운영 목적을 벗어난 분석에 재사용하지 않는다.
